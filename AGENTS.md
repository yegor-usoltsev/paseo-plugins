# paseo-plugins

Each top-level plugin directory (`peer/`, `resume/`) is an independent Paseo plugin with its own `paseo-plugin.json`, `OVERVIEW.md`, `package.json`, `tsconfig.json` and `AGENTS.md`. Keep each one aligned with the `paseo plugin init` template and the [plugin docs](https://paseo.sh/docs/plugins): its `files` list, `typecheck` script, exact-pinned devDependencies (SDK, TypeScript 5.9, React, React Native, Query, Zod) and tsconfig, which adds only `node` types for server code and tests. The Paseo contracts win over lint preferences. Users install one with `paseo plugin install github:yegor-usoltsev/paseo-plugins:<directory>`, so keep each plugin self-contained: no imports across plugin directories and no `tsconfig` `extends` outside the plugin.

Development uses Bun: the root `package.json` is a Bun workspace with `bun.lock` and holds only the lint tooling. Run `bun install` and `bun run test` at the root; `bun run test` runs `bun test` in every workspace. Each plugin declares `@getpaseo/client` and `ws` runtime dependencies and owns a standalone npm `package-lock.json`. Its manifest `build` runs `npm ci --workspaces=false --omit=dev --ignore-scripts`; GitHub installation runs it on the user's daemon host, where Paseo requires only npm, so keep that command and those locks on npm rather than Bun. Directory installation does not run it: prepare a directory plugin with `npm ci --prefix peer --workspaces=false --omit=dev --ignore-scripts` (or `resume`) before install/reload when its lock changes. Keep `bun.lock` and the standalone locks current; CI runs both `npm ci` commands to catch a stale standalone lock. Import SDK types through the host’s `@getpaseo/plugin` to match its context types.

`bun run lint` runs type checking and Ultracite (oxlint and oxfmt) and also runs as the pre-commit hook; `bun run lint:fix` applies fixes. One root `oxlint.config.ts` covers both plugins, and type-aware rules resolve each plugin's `tsconfig.json`. It is the Ultracite presets unchanged, with every JS plugin that applies. Fix a diagnostic first; otherwise ignore it inline with a reason, then for the file, and turn a rule off in the config only when it is frequent and hard to fix. Test fakes cast to SDK types inline with a SAFETY comment. `bun run lint` type-checks each plugin with its own `typecheck` script.

CI runs `bun install --frozen-lockfile`, `bun run lint`, `bun run test` and the standalone `npm ci` commands on Linux and macOS.

The plugin IDs `paseo-peer` and `paseo-resume` are stable: installations, the resume state file and agents' `peer` MCP servers depend on them. Add a new plugin as a new directory and list it in the root `workspaces` and `README.md`.
